# ADR 0014. 룸 메시지는 다음 실행에 전달하고, 에이전트가 떨어져도 담당은 남는다

- 상태: **확정**
- 일자: 2026-10-26

## 맥락

BE 10.25 응답(FE→BE 10.24 요청 1·2)으로 룸에서 사람이 에이전트에게 말하는 API(`POST /projects/{id}/rooms/{role}/messages`)가 생겼다. 그리고 에이전트 연결을 해제해도 그 사람은 역할 담당으로 남는다(A안). 기능명세서에는 아직 이 항목이 없다. 계약은 BE `docs/openapi.yaml`을 따른다.

## 결정

- 입력창은 **그 역할 담당과 대표**에게 보인다. 에이전트가 없거나 오프라인이어도 보낼 수 있다. 서버가 받아 두었다가 **다음 실행의 브리핑**으로 전달하고, 실행 중인 에이전트에 바로 끼워 넣지 않는다. 입력창 아래에 이 사실과 "비밀값을 적지 말 것"을 적는다.
- 낙관적 업데이트는 하지 않는다. 보내는 동안 입력창을 막고, 성공하면 피드를 다시 읽어 오른쪽 말풍선(`speaker: human`)으로 그린다. 실패하면 입력을 남겨 두고 에러 문구를 보여 준다.
- 멘션을 본문 앞에 붙이지 않는다. 본문이 그대로 기록과 브리핑에 들어가기 때문이다.
- `ProjectMember.agentId·agentName`이 null이면 "에이전트 연결 필요"로 표시한다. 대표의 해제는 경로에 `agentId ?? userId`를 넣는다. GitHub 다시 초대는 에이전트가 있을 때만 보인다.

## 결과

- 대표 룸 참여자 표기 "대표 · 보기만"을 "대표"로 바꿨다.
- 1000자 제한은 입력창 `maxLength`로 걸고, 최종 판정은 서버(400 `VALIDATION_ERROR`)가 한다.

## 재검토 조건

- 서버가 실행 중인 에이전트에 메시지를 바로 넣게 되면 안내 문구를 바꾼다.
- 기능명세서에 룸 메시지가 들어오면 그 기준에 맞춘다.
