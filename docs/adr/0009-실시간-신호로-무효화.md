# ADR 0009. 실시간 신호(/api/stream)로 쿼리를 무효화하고, 폴링은 대비용으로

- 상태: **확정** (BE: backend PR #21, 운영 배포됨) · [0004](./0004-당분간-폴링.md)를 대체
- 일자: 2026-10-06

## 맥락

0004는 "BE 실시간 채널 계획이 확정되면 재검토"였다. BE가 사람용 웹소켓 `/api/stream`을 배포했다.

- 서버 변화가 커밋되면(`events` INSERT → DB 트리거 NOTIFY) **"무엇을 다시 읽을지(topics)"만** 보낸다. 데이터는 보내지 않는다
- 조직 신호(`projectId: null`)는 구독 없이, 프로젝트 신호는 그 프로젝트를 **구독한 연결에만** 온다
- 신호는 재전송되지 않는다. 끊긴 사이의 변화는 재연결 뒤 다시 읽어야 한다. 서버가 놓쳤을 수 있으면 `resync`를 보낸다
- **이벤트를 남기지 않는 변화는 신호가 없다** (PM 작업기 접속 여부, 브랜치 등록 등)

## 결정

**신호를 받으면 해당 쿼리를 `invalidateQueries`로 다시 읽는다. 폴링은 지우지 않고 끊긴 동안의 대비용으로 남긴다.**

- 연결: `shared/api/stream.ts`. 브라우저 기본 `WebSocket`, 탭당 하나. 라이브러리를 쓰지 않는다
  - 토큰은 URL이 아니라 연결 뒤 첫 메시지로 보낸다 (프록시 로그에 남지 않게)
  - 재연결은 1초부터 두 배씩 최대 30초. 4401(인증)·4403(조직 없음)·4400·4408은 재연결하지 않는다
  - 레이아웃이 바뀌어 `AuthGate`가 잠깐 내려가도 2초 안에 다시 올라오면 연결을 유지한다
- 매핑: `widgets/auth/useRealtimeSync.ts` 한 파일에 topic → 쿼리 키를 모은다. `AuthGate`가 조직이 있는 사용자에게만 연결한다
- 구독: 프로젝트 화면(`AppShell`)이 `useProjectStream(projectId)`로 들어올 때 구독, 나갈 때 해지
- 재연결(`ready` 재수신)·`resync`·연결 끊김 때 열린 화면 전체를 한 번 다시 읽는다
- 폴링 주기: `livePoll(ms)` — 연결 중 30초, 끊기면 원래 주기(4~5초). 탭이 숨겨지면 멈추는 것은 그대로
- 신호가 없는 곳
  - `pm/status`(작업기 준비 상태): 연결과 상관없이 기존 폴링 유지 + `agents` 신호 때 함께 다시 읽기
  - 팀원 프로젝트 목록: 배정 신호가 `projects`가 아니라 `agents`로 온다 → `agents` 신호 때 함께 다시 읽기 + 기존 10초 폴링 유지
  - 태스크 브랜치 이름: 다음 `tasks` 신호나 대비용 폴링 때 반영 (조치 없음)

## 결과

- 바뀐 순간(약 0.1~0.7초) 화면에 반영되고, 아무 일이 없으면 요청이 거의 없다 (30초 대비용만)
- 기존 쿼리 훅은 그대로 쓴다. 0004에서 "조회는 전부 쿼리 훅으로" 해 둔 덕분에 훅 내부의 폴링 주기만 바꿨다
- 재연결 백오프 때문에 서버가 돌아온 뒤 최대 30초까지 신호가 늦을 수 있다. 그동안은 원래 주기의 폴링이 메운다
- 웹소켓 프로토콜은 OpenAPI로 표현되지 않아 생성 타입이 없다. 메시지 모양은 `stream.ts` 주석과 Swagger 첫 화면 설명이 기준이다

## 재검토 조건

- BE가 신호 없는 변화(작업기 접속, 배정 시 `projects`)에 토픽을 추가했을 때 — 해당 폴링을 줄인다
- 에이전트 실행 로그 스트리밍처럼 데이터 자체를 실어 보내야 하는 요구가 생길 때
