# ADR 0010. API 계약 확정은 Room 3가 아니라 문서 › API 계약 탭에서

- 상태: **대체됨** → ADR 0013 (BE 10.15, frontend PR #59)
- 일자: 2026-10-16

## 맥락

BE 10.15에서 계획 흐름이 세 단계가 됐다: 기능 명세 확정 → 기능별 API 계약 확정 → 태스크 나누기.

- 계약을 확정할 수 있는 사람은 프로젝트의 **BACKEND 담당(에이전트 주인)**, BE 담당이 없으면 대표다. 판정은 서버(403 `NOT_CONTRACT_APPROVER`)
- 나머지 계획 단계가 있는 Room 3(`widgets/pm-room`)는 **대표 전용**이다. BE 담당 팀원은 들어올 수 없다
- 문서 화면에는 목업 "계약" 탭이 이미 있었고, 문서는 프로젝트 멤버 전원이 본다

## 결정

**계약 화면은 문서의 "API 계약" 탭(`widgets/docs`)에 두고, 실제 `GET /projects/{id}/contracts`로 바꾼다.** Room 3에는 계약 현황(n/m 확정)과 계약 탭 링크만 둔다.

- 카드: `entities/contract/ui/ContractCard.tsx` — pending · draft(확정/수정 요청) · approved(잠김) · failed(수정 요청). 수정 요청 남은 횟수 노출
- 버튼은 확정 권한이 있는 사람에게만 보이고, 최종 판정은 서버 403에 맡긴다
- 태스크 나누기는 계약이 덜 끝나도 미리 막지 않는다. 서버 409 `CONTRACTS_NOT_APPROVED`의 `details.featureKeys`를 안내하고 계약 탭으로 보낸다 (판정 주체는 서버)

## 결과

- BE 담당이 Room 3 권한 없이 계약을 확정할 수 있다. Room 3 권한 모델은 그대로다
- 대표는 Room 3 ↔ 문서 탭을 오가야 한다. 링크로 이어 둔다
- 계획 확정 시 명세·계약·태스크 쿼리를 함께 무효화한다. 다른 화면의 다음 단계가 신호 지연 없이 보이게

## 재검토 조건

- Room 3 접근 권한이 BE 담당에게 열릴 때 — 계약 확정을 Room 3 흐름 안으로 옮길지 본다
- 계약 확정자가 BE 담당 외로 넓어질 때
