# ADR 0011. 설정은 한 곳에 탭으로, 온보딩에 GitHub 연동 단계를 필수로, 초대는 프로젝트 생성 흐름에서

- 상태: **확정** (frontend #60)
- 일자: 2026-10-16

## 맥락

- 설정이 계정(`/settings/account`) · 조직(`/org`) · 프로젝트(`/p/{id}/settings`) 세 곳에 흩어져 있었고, 조직 진입점은 글자 링크라 버튼으로 보이지 않았다
- GitHub 연동은 계정 설정 안쪽에만 있어서, 연동하지 않은 팀원은 레포 협업자 초대가 `skipped`로 빠지고 대표는 레포를 고르거나 만들 수 없었다
- 초대 링크 발급은 조직 화면에만 있어서, 프로젝트를 만든 직후 팀원을 부르려면 화면을 옮겨야 했다

## 결정

1. **설정을 탭으로 모은다.** 프로젝트 안에서는 `/p/{id}/settings?tab=project|org|account`, 프로젝트 밖에서는 `/settings/account|org`. 탭은 주소에 둔다(뒤로가기로 돌아오게). `/org`는 `/settings/org`로 넘긴다. 진입점은 "설정" 버튼(목록)과 사이드바 "설정" 하나씩. 계정 메뉴의 톱니는 없앴다
2. **온보딩은 에이전트 연결(1/2) → GitHub 연동(2/2, `/connect/github`).** GitHub 단계는 건너뛸 수 없다(다음 버튼 비활성). 강제는 화면에서만 한다 — `AuthGate`에서 막지는 않는다(기존 미연동 계정이 전부 막히므로)
3. **초대 링크는 프로젝트 생성 흐름의 레포 다음 단계에서도 만든다.** 초대는 조직 단위라 프로젝트가 생기기 전에 만들어도 된다. 건너뛸 수 있고, 나중에는 설정 › 조직에서 만든다

## 결과

- 조직 화면(`OrgView`)·계정 화면(`AccountSettingsView`)은 페이지 틀 없이 내용만 그린다. 틀은 부르는 쪽(`SettingsFrame` 또는 프로젝트 설정 페이지)이 그린다. 위젯끼리 import할 수 없어서 탭 조합은 `page.tsx`가 한다
- GitHub 연동 UI는 `entities/user/ui/GithubConnect`로 옮겨 계정 설정과 온보딩이 함께 쓴다

## 재검토 조건

- GitHub 미연동 사용자를 서버가 막기 시작하면 — `AuthGate`에서 `/connect/github`로 보내는 것을 검토
- 초대가 프로젝트 단위로 바뀌면 — 초대 단계를 프로젝트 생성 뒤로 옮긴다
