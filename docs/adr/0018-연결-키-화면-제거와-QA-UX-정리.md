# ADR 0018. 연결 키를 화면에서 빼고 가입을 3단계로 줄인다 · QA에서 정한 표시 규칙

- 상태: **확정**
- 일자: 2026-11-19

## 맥락

전체 QA(#94)에서 정한 것들이다. 에이전트는 `/connect`의 1회용 명령으로 연결하므로(adr/0008) 연결 키는 SSH처럼 브라우저를 못 여는 환경에서만 쓰였다. 그런데 가입 2단계가 키를 보여 주고 저장을 확인받느라 모든 사용자가 쓰지 않을 키를 한 번 거쳐야 했다.

## 결정

- **연결 키를 화면에서 뺀다.** 가입의 "연결 키" 단계, `/connect`의 "연결 키로 로그인" 안내, 계정 설정의 "연결 키 재발급"을 지운다. 가입은 계정 → 에이전트 연결 → GitHub 연동 3단계다. 가입 응답의 `connectKey`는 쓰지 않는다. 서버 API(`/me/connect-key/rotate`, CLI `--connect-key`)는 그대로다.
- **단계 표시는 가입 중에만.** GitHub 연동까지 마친 사용자가 `/connect`에 다시 오면 "n / 3단계"를 보이지 않는다.
- **에이전트 연결 진입점은 설정 › 계정의 버튼.** 사이드바 사용자 메뉴에서는 뺀다.
- **사이드바는 프로젝트 이름만.** 레벨·상태 배지는 대시보드 머리에 있다. 실험 모드 배지만 남긴다. 룸 옆 에이전트 상태 점도 뺀다(안 읽은 메시지처럼 보였다). 상태는 대시보드 "에이전트 · 레포"에 있다.
- **대시보드 태스크 타일의 "완료"는 칸반 완료 칸과 같은 기준**(`DONE` + `CANCELLED`)으로 센다.
- **서버 값은 한글로 바꿔 보인다.** 검증 결과(통과·실패·건너뜀), 태스크 종류(구현·통합·재작업), 승인 방식(자동). 모르는 이벤트 종류는 type 이름 대신 "기타 활동"으로 보인다. 평가 화면은 대표용 실험 화면이라 그대로 둔다.
- **서버 내부 메시지는 드러내지 않는다.** 건너뛴 검증 단계의 사유는 "자세히"로 접고, 질문 카드의 라우터 실패 원문은 보이지 않는다. 실패(FAIL) 사유는 고쳐야 하므로 그대로 보인다.
- **조사는 `josa()`로 붙인다** (`shared/lib/format`). 화면이 만드는 문장에만 해당한다 — 서버가 문장째 주는 글(알림·룸 메시지·결정 요약)은 서버가 고친다.
- **볼 수 없는 룸은 `RoomForbidden` 하나로** 보인다 (대표 룸·역할 룸 공통).
- **편지함은 들어왔을 때 안 읽었던 알림에 "새" 배지**를 이번 방문 동안 단다. 열자마자 읽음 처리되는 것은 그대로다(adr/0016).
- **팀원에게 다른 역할의 태스크가 보여도 된다.** 명세 F-14의 "FE가 보면 BE 태스크는 안 보임"과 다르다 — 대시보드 칸반은 프로젝트 전체를 보인다.

## 재검토 조건

- 브라우저를 열 수 없는 환경의 사용자가 생기면 연결 키 안내를 계정 설정에 되살린다.
- 서버가 검증 사유를 코드로 내려주면 단계별 고정 문구로 바꾼다.
