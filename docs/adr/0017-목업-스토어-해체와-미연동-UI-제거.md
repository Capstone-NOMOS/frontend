# ADR 0017. 목업 스토어를 지우고, API가 없는 화면 요소는 두지 않는다

- 상태: **확정**
- 일자: 2026-11-19

## 맥락

전체 QA(#94)에서 API가 연결되지 않은 요소가 실제 화면에 남아 있는 것을 확인했다. 대시보드의 "사용량" · "이번 기능 비용", 활동 화면의 "비용" 탭, 사용자 메뉴의 "데모 데이터 초기화" · "데모: 역할 전환", 프로젝트 설정의 "변경 기능은 준비 중입니다", 랜딩의 "데모 계정으로 둘러보기", 그리고 `/rooms/<알 수 없는 값>`이 떨어지던 목업 룸 화면이다.

실제 프로젝트 id는 목업 스토어에 없으므로 이 요소들은 늘 비어 있거나 ₩0만 보였다. "목업" 배지를 달아 두는 규칙(architecture.md §10)은 사용자에게 고장처럼 보이는 화면을 남겼다.

## 결정

- 위 요소를 전부 지운다. 비용 API가 없으므로 메뉴 이름도 "활동 · 비용"에서 "활동"으로 바꾼다.
- 룸 주소는 `owner` · `frontend` · `backend`뿐이다. 그 밖의 값은 `notFound()`로 404를 낸다.
- 쓰는 곳이 없어진 `lib/store.tsx` · `lib/mock/seed.ts` · 목업 `RoomView` · `Cards` · `MockBadge` · `MockEmpty`를 지우고, 린트의 `mock-store` 예외도 없앤다. `src/lib/`은 사라진다.
- 앞으로 API가 없는 화면 요소는 목업 데이터로 채우지 않는다. API가 생기면 그때 만든다.

## 재검토 조건

- 비용·사용량 API(F-17)가 생기면 대시보드 카드와 활동 화면의 비용 보기를 쿼리 훅으로 다시 만든다.
- 프로젝트 기본 정보 수정 API가 생기면 설정 화면에 편집을 붙인다.
- 스토어만 쓰던 엔티티 타입(`Message` · `Card` 등)이 남아 있을 수 있다. 쓰는 곳이 없으면 따로 정리한다.
