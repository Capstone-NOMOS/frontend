# ADR 0021. 활동 로그는 화면에 걸린 줄만 그린다

- 상태: **확정**
- 일자: 2026-11-23

## 맥락

- 활동 화면의 이벤트 로그는 받아 둔 이벤트를 전부 그렸다. "더 보기"로 펼칠수록 DOM과 다시 그리기 비용이 건수에 비례해 늘었다 — 3,000건이면 DOM 노드 21,158개, 새 이벤트 하나에 렌더 774ms
- `@tanstack/react-virtual`은 이 용도로 설치해 두고 쓰지 않고 있었다 (adr/0019에서 남기기로 함)

## 결정

- `ActivityView`의 `Events`에 `useVirtualizer`를 적용한다. 화면에 걸린 줄과 위아래 8줄만 그린다
- 줄은 절대 위치로 띄우지 않고 **흐름 그대로** 둔다. 그리지 않은 줄의 자리는 `<ol>`의 위아래 padding으로 잡는다 — `<ol>` › `<li>` 구조와 줄 사이 구분선(`divide-y`)이 그대로 남고, `EventRow`는 `ref` · `data-index`만 받게 열면 된다
- 줄 높이는 37px로 추정하고 그려진 뒤에 잰다 (`measureElement`). 좁은 화면에서 두 줄로 접히는 줄이 있다
- **스크롤 위치는 가상화가 잡는다.** 목록 첫 줄이 화면 위로 지나간 뒤에는 `anchorTo: "end"`로 두어, 새 이벤트가 맨 앞에 끼어들어도 보던 줄이 key 기준으로 제자리에 남는다. 맨 위에 있을 때는 `"start"`로 두어 새 이벤트가 바로 보인다. 브라우저의 보정과 겹치지 않게 스크롤 요소에 `overflow-anchor: none`을 건다
- 스크롤 요소는 `ref`가 아니라 **state**로 넘긴다. 캐시가 있어 첫 렌더부터 목록을 그릴 때(재진입) 자식의 layout effect가 부모의 ref보다 먼저 돌아, ref로는 가상화가 스크롤 요소를 잡지 못한다
- 같이 고친 것 — 가상화하면 스크롤이 React를 거치게 되어 아래 둘이 프레임을 잡아먹었다
  - `shared/lib/format.ts`: `Intl.DateTimeFormat`을 한 번만 만든다
  - `entities/event/api/eventApi.ts`: `select` 함수를 훅 밖에 둔다. `EventRow`는 `memo`

## 하지 않는 것

- 자동 무한 스크롤. "더 보기" 버튼을 유지한다
- 룸 피드 가상화. 질문 카드에 쓰던 답이 사라지는 문제가 있다 (docs/perf-room-feed.md)
- 새 이벤트 때 첫 페이지만 다시 읽기. 받아 둔 페이지를 전부 다시 읽는 것은 그대로다

## 치른 비용

- 스크롤이 공짜가 아니게 됐다. 변경 전에는 스크롤 중 React 커밋이 0이었고, 지금은 프레임마다 4번이다. 빠르게 내릴 때 프레임 간격 p95가 17.0 → 21.6ms
- 화면에 없는 줄은 DOM에 없다. 브라우저의 페이지 내 찾기(Ctrl+F)로 펼쳐 둔 옛 이벤트를 찾을 수 없다
- 린트 예외 두 줄 (`react-hooks/incompatible-library`, `react-hooks/exhaustive-deps`). 이유는 코드 주석에 적었다. React Compiler를 켜게 되면 앞의 것을 다시 볼 것

## 측정

이벤트 3,000건을 전부 펼친 상태, 프로덕션 프로파일링 빌드, 헤드리스 Chrome, 5회 중앙값. 방법과 단계별 값은 [perf-activity.md](../perf-activity.md).

| | 변경 전 | 가상화 없이 포매터 · `select`만 | 변경 후 |
| --- | --- | --- | --- |
| 처음 그리기 (React 커밋 시간 합) | 680.5ms | 140.1ms | 3.1ms |
| 새 이벤트 1건 | 773.8ms | 38.9ms | 3.1ms |
| 스크롤 프레임 간격 (중앙값 / p95) | 16.7 / 17.0ms | 16.7 / 17.0ms | 17.2 / 21.6ms |
| DOM 노드 수 | 21,158 | 21,158 | 347 |
| JS heap | 21.2MB | 21.3MB | 9.5MB |

3,000건은 "더 보기"를 100번 누른 상태다. 처음 들어오면 30건만 받는다.
