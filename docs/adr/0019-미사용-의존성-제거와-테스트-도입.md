# ADR 0019. 쓰지 않는 의존성을 지우고, 핵심 흐름만 Vitest로 테스트한다

- 상태: **확정**
- 일자: 2026-11-19

## 맥락

- `package.json`에 zustand · msw · react-markdown · remark-gfm · rehype-sanitize가 있었지만 `src`에서 한 번도 import되지 않았다. 초기 설계 때 "쓸 예정"으로 넣어 둔 것이고, 그 자리는 React Query(서버 상태) · 자체 마크다운 파서 · 로컬 BE로 채워졌다. 설치돼 있다는 이유로 "쓰는 스택"처럼 읽히는 것이 문제였다
- 테스트가 0건이었다. 화면은 브라우저에서 눈으로 확인해 왔지만, 실시간 재연결 · 신호 매핑 · 중복 제출 방지처럼 **화면으로는 확인하기 어렵고 틀리면 조용히 망가지는** 로직에 안전망이 없었다

## 결정

- 위 5개를 지운다. `@tanstack/react-virtual`은 활동 로그 가상화에 쓸 것이라 남긴다
- 테스트 러너는 Vitest. `environment: "node"`만 쓰고 jsdom · React Testing Library는 넣지 않는다. 브라우저 API(`WebSocket` · `fetch`)는 테스트가 직접 스텁한다
- 테스트는 소스 옆 `*.test.ts`에 둔다. 대상은 네 가지다
  - `shared/api/stream.ts` — 인증 첫 메시지, 재구독, 백오프 재연결(1초 → 최대 30초), 재연결하지 않는 닫힘 코드, resync, 대비용 폴링 주기
  - `widgets/auth/useRealtimeSync.ts` — 신호가 어떤 쿼리를 다시 읽게 하는가 (react-query의 실제 키 매칭으로 확인)
  - `shared/api/client.ts` — 쓰기 요청 중복 제거, 401 처리, 네트워크 오류
  - `widgets/auth/safeNext.ts` — 열린 리다이렉트 차단
- 테스트하려고 훅 안의 로직을 훅 밖 함수로 뺐다: `keysForSignal`, `subscribeProject`, `onStreamSignal`, `acquire`(export). 훅은 이 함수들을 부르기만 한다. 동작은 바뀌지 않았다
- `stream.ts`는 연결 상태를 모듈 전역에 두므로 테스트마다 `vi.resetModules()` 뒤 다시 import한다
- CI의 Typecheck 뒤에 `pnpm test`를 넣는다
- Vitest는 4.x를 쓴다. 5.x는 Node 22.12 이상을 요구하는데 이 프로젝트의 하한(`engines`)은 20.9다
- CI의 Node를 20.9에서 22로 올린다. Vitest가 쓰는 vite 8이 Node 20.19 이상을 요구한다. `engines`와 배포 설정은 그대로 둔다 — 대신 CI는 더 이상 하한(20.9)에서 검증하지 않는다

## 하지 않는 것

- 컴포넌트 렌더 테스트, E2E, 커버리지 목표. 화면은 지금처럼 로컬 BE에 붙여 브라우저로 확인한다
- 테스트를 위한 구조 변경. 훅 밖으로 함수를 빼는 것 이상은 하지 않는다

## 재검토 조건

- 화면 로직(폼 검증 · 카드 상태 분기)에서 회귀가 반복되면 jsdom + RTL을 그 범위에만 들인다
- 마크다운에 표 · 각주 같은 문법이 필요해지면 react-markdown을 다시 검토한다 (그때는 `rehype-sanitize`와 함께)
