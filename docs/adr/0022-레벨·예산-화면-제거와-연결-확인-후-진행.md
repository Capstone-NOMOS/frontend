# ADR 0022. 레벨·예산을 화면에서 빼고, 에이전트 연결은 확인된 뒤에 넘어간다

- 상태: **확정**
- 일자: 2026-11-26 ([#111](https://github.com/Capstone-NOMOS/frontend/issues/111))

## 맥락

QA 피드백. 허용 레벨(L1~L4)과 예산(PM 예산·전체 예산)은 사용자가 정할 이유가 약한데, 프로젝트를 만들 때 두 단계를 더 거쳐야 했고 설정·대시보드·목록·대표 룸에 계속 보였다.
명세(§0-1 정책표, F-08 예산 게이트, S-9 설정)와 다르지만 사용자가 정한 것이다.

서버 `POST /orgs/{orgId}/projects`는 `autonomyPreset`·`pmBudgetUsd`를 **아직 필수로** 받고 기본값이 없다.

## 결정

- **프로젝트 생성은 이름 → 레포 → 초대 → 선택(마감일·질문 중계).** 레벨·PM 예산 단계와 전체 예산 입력을 없앤다.
  생성 요청에는 `autonomyPreset: "L2"`, `pmBudgetUsd: 100`을 고정으로 보낸다(`ProjectNewView`의 상수).
- **레벨·예산 표시를 지운다.** 설정의 레벨·예산 줄과 허용 레벨 정책표, 대시보드·프로젝트 목록·사이드바 전환 목록의 레벨 배지와 PM 예산, 대표 룸의 예산 막대·80% 경고. `entities/policy`는 쓰는 곳이 없어 지웠다.
  대표 룸은 **예산을 다 썼을 때만** "새 계획 요청은 거절됩니다"를 보인다 — 숨긴 예산이 바닥나면 PM이 왜 멈췄는지 알 길이 없어서다.
- 랜딩의 "허용 레벨(L1–L4)"·"17가지 행동을 L1–L4 표로" 문구를 실제 흐름(이름·레포·초대, 서버가 판정하는 승인)으로 바꾼다.
- **에이전트 연결 화면의 버튼은 켜진(`online`) 내 에이전트가 보여야 누를 수 있다.** 가입 중이면 "다음"(→ GitHub 연동), 설정에서 왔으면(`/connect?next=…`) "완료"(→ 그 설정 화면). `next`는 `safeNext`로 같은 사이트 경로만 받는다. 조직이 없으면 에이전트 목록을 볼 수 없으므로 막지 않는다.
- **설정 › 계정의 "에이전트 연결"은 켜진 내 에이전트가 없을 때만** 누를 수 있다(처음 연결·꺼진 에이전트 다시 켜기).
- 받은 편지함 알림은 활동 화면처럼 **"더 보기"**로 이어 읽는다. 응답에 다음 커서가 없어서 꽉 찬 페이지(30개)면 더 있다고 보고, 마지막 `id`를 `before`로 보낸다.
- 명세 탭의 기능 명세는 API 탭과 같은 **카드**로 보인다.
- 사이드바 좌측 하단의 계정 메뉴 토글을 없애고 **로그아웃 버튼**을 둔다.
- **로그아웃은 랜딩(`/`)으로**, 전체 새로 불러오기로 간다. 화면 안 이동이면 세션이 지워지는 순간 AuthGate가 먼저 `/login?next=…`로 보낼 수 있다.
- **로그인 직후 랜딩이 깜빡이지 않게** 로그인 성공 시 `/`가 아니라 `/projects`로 바로 보내고, 랜딩은 `/me`를 기다리지 않고 토큰만 있으면 `/projects`로 보낸다(`useHasSession`).

## 결과

- 레벨은 모든 프로젝트가 L2다. 서버의 정책표는 그대로 판정한다.
- 로그인한 채 `/`를 직접 열면 하이드레이션 전 한 프레임은 서버가 그린 랜딩이 보인다. 토큰이 sessionStorage에 있어 서버가 모른다(adr/0007).

## BE 전달 사항

- `POST /orgs/{orgId}/projects`의 `autonomyPreset`·`pmBudgetUsd`를 선택값으로(서버 기본 `L2`·`$100`). 바뀌면 FE 상수를 지운다.
- (선택) `GET /me/notifications` 응답에 `nextBefore`를 주면 "꽉 찬 페이지면 더 있다" 추정을 대체한다.

## 재검토 조건

- 레벨·예산을 프로젝트마다 다르게 둘 필요가 생기면 설정에서 바꾸는 API와 함께 되살린다.
