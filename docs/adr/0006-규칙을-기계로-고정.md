# ADR 0006. 규칙을 기계로 고정한다 (Prettier · 경계 린트 · CI)

- 상태: 확정 · 이행 완료 (#6)
- 일자: 2026-09-26

## 맥락

`AGENTS.md`·`conventions.md`·`design.md`에 규칙을 적어뒀지만 **전부 문서로만 막고 있었다.** 그리고 레포에 CI가 없어서 PR에 통과·실패 게이트가 하나도 없었다. 린트·타입체크·빌드는 각자 로컬에서만 돌았다.

ADR 0002가 이미 경고한 상태였다.

> 경계 린트를 CI에 넣는다. **린트가 없으면 폴더 이름만 바뀌고 규칙은 한 달 안에 무너진다.**

FSD 이행(#4)은 끝났지만 경계는 grep으로만 확인된 상태였다. 포맷터도 없어 사람마다 다르게 저장하면 diff에 포맷 변경이 섞였다.

## 결정

**문서로만 막던 규칙 중 기계로 옮길 수 있는 것을 옮기고, CI를 머지 게이트로 세운다.**

CI는 `format:check → lint → typecheck → build` 4단계다.

### 세부 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| Prettier `printWidth` | **120** | 기존 코드 줄 길이가 median 30 / p90 105 / max 383. 기본값 80이면 90%의 줄이 재배치돼 도입 PR의 diff를 읽을 수 없게 된다 |
| 마크다운 | **포맷 대상에서 제외** | 명세서 2개가 판단 기준 문서이고(`AGENTS.md`), `AGENTS.md`에는 `next dev`가 재생성하는 관리 블록이 있다. 표 패딩 재배치는 이득 없이 diff만 늘린다 |
| 경계 린트 | `eslint-plugin-boundaries` v7 | `default: "disallow"` 하나로 레이어 역방향과 슬라이스 교차가 동시에 막힌다. 같은 슬라이스 내부 import는 같은 요소라 영향받지 않는다 |
| `src/lib` | `mock-store` 타입으로 **예외 등록** | 해체 예정(`architecture.md` §8)이라 규칙을 우회하는 게 아니라 한시적 예외임을 설정에 명시한다. 스토어가 사라지면 이 항목도 함께 지운다 |
| CI의 `build` | **포함** | Vercel도 빌드하지만 그 체크는 프로젝트 설정에 따라 꺼질 수 있다. 캐시를 쓰므로 추가 비용이 1분 미만이다 |
| `typecheck` | `next typegen && tsc --noEmit` | Next 16이 생성하는 `LayoutProps`·`PageProps`는 `next dev`·`build`·`typegen` 중 하나를 거쳐야 존재한다. CI에만 단계를 넣으면 새로 클론한 팀원이 같은 실패를 겪는다 |
| 줄 끝 | `.gitattributes`로 `eol=lf` | Prettier 기본값이 LF인데 `core.autocrlf=true`인 Windows는 CRLF로 체크아웃한다. 고정하지 않으면 **로컬만 실패하고 CI는 통과**해서 결과가 어긋난다 |

## 결과

- 이후 모든 PR은 4단계를 통과해야 머지할 수 있다
- 경계 규칙은 이제 문서가 아니라 린트가 판정한다. `conventions.md`의 레이어 표는 설명이지 근거가 아니다
- `pnpm format`·`pnpm lint`·`pnpm typecheck`로 로컬에서 CI와 같은 것을 돌릴 수 있다
- CD는 범위 밖이다. Vercel Git 연동이 담당하며 프로덕션 브랜치는 `main`이다

### 도입 중 CI가 잡은 것

로컬에서 4단계가 전부 통과한 상태였는데도 첫 CI 실행이 두 가지를 잡았다. **게이트가 있어야 하는 이유 자체가 증명됐다.**

1. `next typegen` 없이는 깨끗한 체크아웃에서 `LayoutProps`를 찾지 못한다 — 로컬은 `.next/types`가 남아 있어 통과했다
2. 줄 끝 불일치 — 로컬과 CI의 판정이 달랐다

## 아직 기계로 막지 못한 것

문서로만 막고 있는 규칙이 남아 있다. 이것들은 여전히 리뷰어가 봐야 한다.

- `middleware.ts` 생성 금지 (→ `proxy.ts`) — 파일 존재 검사 한 줄로 가능
- **토큰에 없는 색 사용 금지** — 현재 코드에 이미 20곳 위반이 있다. 규칙을 켜려면 먼저 정리해야 한다
- 낙관적 업데이트 금지, 요청 중 버튼 비활성화 — 정적 검사로 표현하기 어렵다

## 재검토 조건

1. Vercel이 PR 상태 체크를 안정적으로 거는 것이 확인되면 CI의 `build` 단계를 뺀다
2. CI 실행 시간이 리뷰 흐름을 방해할 정도로 길어지면 단계를 병렬 잡으로 쪼갠다
3. 경계 린트의 예외 목록이 `mock-store` 외에 늘어나기 시작하면, 예외를 늘리지 말고 레이어 설계를 다시 본다
