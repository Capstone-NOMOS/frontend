# ADR 0007. 헤더 토큰과 클라이언트 가드

- 상태: 확정
- 일자: 2026-09-29

## 맥락

BE API는 쿠키를 쓰지 않는다. 토큰은 로그인 응답 body로 받고 `Authorization: Bearer` 헤더로 보낸다. fetch에 `credentials: 'include'`를 넣지 않는다.
사람 토큰의 유효기간은 24시간(로그인 응답 `expiresIn: 86400`)이고 refresh가 없다.

따라서 Next 서버(`proxy.ts`, 서버 컴포넌트)는 사용자 토큰을 볼 수 없다. ADR 0001이 전제한 "`proxy.ts`로 JWT를 검증하는 서버 가드"는 성립하지 않는다.

## 결정

**토큰은 `sessionStorage`에 보관하고, 라우트 보호는 클라이언트 가드로 한다. 권한의 근거는 API의 401·403이다.**

- 클라이언트 가드는 화면 전환용일 뿐이다. 접근 가능 여부의 최종 판정은 서버 응답으로 한다
- 401을 받으면 토큰을 지우고 로그인 화면으로 보낸다. 403은 권한 없음으로 표시한다

## 결과

- `proxy.ts`·`middleware.ts`를 만들지 않는다
- 로그인이 필요한 데이터는 클라이언트에서만 불러온다
- 서버 컴포넌트는 인증 없는 API(예: 초대 미리보기)만 부른다
- 24시간 만료 시 재로그인한다
- ADR 0001의 근거 2("`proxy.ts`가 Node 런타임이라 JWT 가드에 유리")는 이 ADR로 폐기된다. 16 유지 결정 자체는 나머지 근거로 유효하다

## 재검토 조건

아래 중 하나가 발생하면 다시 논의한다.

1. BE가 사람 토큰 refresh를 제공할 때
2. 서버에서 인증 데이터를 렌더해야 할 필요가 생길 때
