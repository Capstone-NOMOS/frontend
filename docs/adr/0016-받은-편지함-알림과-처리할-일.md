# ADR 0016. 받은 편지함은 서버의 알림·처리할 일을 그대로 보이고, 토스트는 직접 만든다

- 상태: **확정**
- 일자: 2026-10-29

## 맥락

BE 10.29 전달(노션 "be to fe 10.29"). 서버가 `GET /me/notifications`(일어난 일, 읽음)와 `GET /me/inbox`(지금 손댈 일, 처리하면 빠짐)를 만들고 문장(`text`)까지 준다. 둘 다 조직 전체 기준이다. 새 조직 토픽 `inbox`가 오면 다시 읽고, 직전 목록에 없던 항목을 새 알림으로 띄우라고 했다.

그전 편지함은 프로젝트 이벤트를 걸러 "알림"을 만들고, 배지는 질문·승인 수를 화면이 직접 셌다.

## 결정

- 새 페이지를 만들지 않고 프로젝트 편지함(`/p/[id]/inbox`)을 고친다. 맨 위 "처리할 일"과 맨 아래 "알림"은 조직 전체 목록이고, 다른 프로젝트 항목에는 프로젝트 이름을 붙인다. 이 프로젝트의 승인 카드는 그대로 두고, 처리할 일의 승인은 그 카드로 가는 `#id` 링크다 (사용자 선택).
- 에이전트 질문 칸은 편지함에서 뺀다. 답을 기다리는 질문은 역할 룸에 이미 답할 수 있는 카드가 있고, 답이 정해진 질문은 결정기록에 쌓여 두 화면과 겹쳤다. 처리할 일·알림의 질문은 그 룸의 카드(`/rooms/{역할}#질문id`)로 보낸다 — 답할 역할의 룸, PM 질문은 묻는 쪽 룸(묻는 역할은 `/me/questions`에서). 답이 정해진 질문 알림은 결정기록으로 (사용자 선택).
- 편지함 배지는 서버의 `counts` 합계와 `unreadCount`를 쓴다. 화면이 따로 세지 않는다.
- 편지함을 열면 맨 위 알림 id까지 읽음 처리한다. 이벤트 id는 문자열 그대로 다룬다.
- 새 항목은 `AuthGate`의 `InboxAlerts`가 토스트로 띄운다. 이 컴포넌트가 두 목록을 늘 붙잡고 있어 어느 화면에서든 신호로 다시 읽힌다. 토스트 라이브러리는 추가하지 않는다.
- 탭이 가려져 있으면 브라우저 알림(`Notification`)도 띄운다. 권한은 편지함의 "브라우저 알림 켜기" 버튼을 눌렀을 때만 묻는다 (사용자 선택).

## 재검토 조건

- 조직 단위 편지함 페이지가 필요해지면 위 두 목록을 그대로 옮긴다.
- 알림이 30개를 넘게 쌓이는 일이 잦으면 `before` 커서로 "더 보기"를 붙인다.
