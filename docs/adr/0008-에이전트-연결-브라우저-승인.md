# ADR 0008. 에이전트 연결을 브라우저 승인으로

- 상태: **확정** (BE 구현: [backend#5](https://github.com/Capstone-NOMOS/backend/issues/5), backend PR #6)
- 일자: 2026-10-01

## 맥락

지금은 CLI(`executor login`)에 **가입 때 한 번만 보여주는 연결 키**를 붙여넣어야 연결된다.
키를 잃어버리면 재발급 → 복사 → 붙여넣기를 거쳐야 해서, 온보딩에서 마찰이 가장 크다.

브라우저는 사용자 노트북에 자격 증명을 쓰거나 프로그램을 실행할 수 없다. 그래서 터미널 명령 1회는 피할 수 없다.
줄일 수 있는 것은 키를 옮겨 적는 과정이다.

## 결정

**에이전트 연결의 기본 방식을 브라우저 승인(OAuth Device Authorization Grant, RFC 8628)으로 바꾼다.**
연결 키는 브라우저를 열 수 없는 환경(SSH 등)을 위해 남긴다.

- CLI가 코드와 링크를 띄우고 브라우저를 연다. 로그인된 사용자가 `/connect/device`에서 코드를 확인하고 승인하면, CLI가 폴링으로 토큰을 받는다
- 승인 화면은 코드·에이전트 이름·요청 IP·요청 시각을 보여주고 "내가 실행한 게 아니면 거부하라"고 경고한다. device flow의 대표 공격인 피싱(남의 CLI가 연 링크를 승인시키기)에 대비하기 위해서다
- 승인·거부는 낙관적 업데이트 없이 서버 응답으로만 상태를 바꾼다
- API 계약은 backend#5를 따르고, 타입은 생성된 `Schemas["DeviceRequest"]`를 쓴다

## 결과

- 기본 경로에서 연결 키 복사·붙여넣기가 사라진다
- CLI가 여는 승인 링크는 BE의 `FRONTEND_BASE_URL` 기준이다. **그 주소에 배포된 프론트가 `/connect/device`를 가진 버전이어야 한다**
- 연결 키 경로의 명령은 `npm run executor -- login <주소> --connect-key`다. `--` 없이 쓰면 npm이 `--connect-key`를 자기 옵션으로 가져가 스크립트에 닿지 않는다
- 설치형 CLI(npm 배포)는 별도 작업이다. npm의 `nomos` 패키지는 다른 사람 소유라서, 랜딩의 `npx nomos connect` 문구를 걷어냈다

## 재검토 조건

- BE 구현 과정에서 API 계약이 바뀌었을 때
- CLI를 npm에 배포할 때 (화면의 명령어 안내 교체)
