# ADR 0004. 당분간 폴링으로 갱신

- 상태: **대체됨** → [0009](./0009-실시간-신호로-무효화.md) (BE가 `/api/stream`을 배포)
- 일자: 2026-09-28

## 맥락

기능명세서 F-14는 대시보드가 "새로고침 없이 갱신(WebSocket)"되는 것을 수용 기준으로 둔다.
그러나 현재 BE API 명세에는 WebSocket·SSE 엔드포인트가 없고, 노트 조회 API의 `since_seq`는 **폴링용**으로 설계돼 있다.
실시간 전송 방식(네이티브 WebSocket / Socket.IO / SSE)은 BE와 함께 정해야 하는 계약 사항이다.

## 결정

**BE 계획이 확인될 때까지 조회 API를 주기적으로 다시 부르는 폴링으로 화면을 갱신한다.**

- TanStack Query의 `refetchInterval` 사용. 대시보드·태스크 목록 3~5초, 문서·설정은 폴링하지 않음
- 탭이 숨겨지면 폴링 중단, 돌아오면 즉시 1회 갱신
- 노트는 `since_seq`로 증분 조회
- **모든 조회를 쿼리 훅으로 감싼다.** 실시간 채널이 생기면 훅 내부만 교체한다
- 실시간 라이브러리는 설치하지 않는다

## 결과

- 3~5초 지연이 생긴다. 조회 위주 화면에는 허용 가능하다
- 에이전트 실행 로그 스트리밍(F-03)과 오프라인 30초 감지는 **구현하지 않는다** — 폴링으로 적합하지 않고, 받을 API도 없다
- 승인·질의 카드가 채팅에 즉시 뜨는 경험은 약해진다 (해당 API도 아직 없음)

## 재검토 조건

- BE가 실시간 채널 계획(방식·일정)을 확정했을 때
- 로그 스트리밍 또는 에이전트 상태 API가 추가될 때
- 폴링 부하가 문제가 될 때
