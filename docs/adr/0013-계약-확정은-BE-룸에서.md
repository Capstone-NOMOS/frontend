# ADR 0013. API 계약 확정은 BE 룸에서, 문서(MCP)는 읽기 전용

- 상태: **확정** (ADR 0010을 대체)
- 일자: 2026-10-24

## 맥락

ADR 0010에서는 계약 확정을 문서 › API 계약 탭에 두었다. 써 보니 "문서(MCP)"는 에이전트가 읽는 문서를 모아 둔 곳인데, 같은 곳에서 승인까지 하니 두 역할이 섞였다. BE 담당은 BE 에이전트와 대화하는 BE 룸에 있는데, 계약을 확정하려면 문서 탭으로 따로 가야 했다.

## 결정

- 확정·수정 요청은 **BE 룸**에서 한다. 확정할 계약(draft·failed)을 피드 아래에 `ContractCard`로 둔다. 확정자는 그대로 BE 담당이고, BE 담당이 없으면 대표다. 최종 판정은 서버(403 `NOT_CONTRACT_APPROVER`)가 한다.
- 문서 › API 계약은 **읽기 전용**(`canDecide={false}`)으로 바꾸고 BE 룸 링크를 둔다.
- 대표 룸(TaskSplitStep · PlanCard)의 계약 링크도 BE 룸으로 바꾼다.
- 같은 이유로 인계 노트는 활동 · 비용에서 문서 › 인계 노트(`/docs/notes`)로 옮긴다. 에이전트가 남기고 에이전트가 읽는 기록이기 때문이다.
- 프로젝트 시작은 대표 룸의 마지막 태스크 확정 카드에서 바로 한다(`StartProject`). 설정의 시작 섹션은 그대로 둔다.

## 결과

- 대표는 BE 담당이 없을 때 BE 룸에 들어가 확정한다. 대표는 모든 룸을 볼 수 있다.
- 피드에 계약 줄(`contractId`)이 없어서, 카드는 대화 흐름 안이 아니라 피드 아래에 모아 둔다.

## 재검토 조건

- 룸 피드에 계약 이벤트 줄이 생기면, 질문 카드처럼 그 줄 위치에 카드를 펼친다.
