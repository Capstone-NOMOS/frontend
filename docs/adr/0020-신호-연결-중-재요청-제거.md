# ADR 0020. 신호가 연결돼 있는 동안은 화면을 오가도 다시 읽지 않는다

- 상태: **확정**
- 일자: 2026-11-20

## 맥락

- `staleTime` 기본값이 0이라 모든 쿼리가 받자마자 낡은 것으로 취급됐다. 화면을 옮기거나 탭으로 돌아올 때마다 같은 API를 다시 불렀다 — 대시보드 → 활동 → 대시보드로 돌아오면 10건
- 그런데 adr/0009 이후 변화는 웹소켓 신호로 온다. 연결돼 있는데 신호가 없었다면 바뀐 것이 없다. 이 재요청은 같은 응답을 다시 받는 일이다

## 결정

- 전역 `staleTime`을 `liveStaleTime`(`shared/api/stream.ts`)으로 둔다. 신호 연결 중 30초, 끊겨 있으면 0
- 30초는 대비용 폴링 주기(`FALLBACK_POLL_MS`)와 같은 값이다. 신호가 없는 쿼리(문서·설정, 이벤트를 남기지 않는 변화)도 화면에 다시 들어오면 30초 안에 갱신된다 — 연결 중 폴링이 이미 허용하던 낡음과 같은 상한이다
- 신호·`resync`·변경 요청 뒤의 `invalidateQueries`는 `staleTime`과 상관없이 다시 읽게 한다. 화면에 없는 쿼리도 무효 표시가 남아 다음에 들어올 때 다시 읽는다
- 끊겨 있으면 0으로 돌아가 이전과 똑같이 동작한다

## 하지 않는 것

- `Infinity`. 신호 매핑에 빠진 쿼리가 있으면 영영 갱신되지 않는다
- 쿼리별 `staleTime` 조정. 전역 한 곳으로 충분하다 (`useMe`의 `Infinity`는 그대로)

## 측정

로컬 BE · 개발 모드 · 신호 연결 상태. 대시보드를 연 뒤 사이드바로 대시보드 → 활동 → 대시보드를 2.5초 간격으로 3번 왕복하며 `/api` 요청 수를 셌다 (Resource Timing).

| | 활동으로 이동 | 대시보드로 복귀 | 왕복 3회 합계 |
| --- | --- | --- | --- |
| 이전 (`staleTime: 0`) | 3건 | 10건 | 39건 |
| 이후 (30초 안) | 0건 | 0건 | 0건 |

30초가 지난 뒤 돌아오면 이전처럼 다시 읽는다 (복귀 8건 확인).
