# ADR 0023. 목록은 10개 뒤 20개씩, 칸반은 칸 안에서 스크롤한다

- 상태: **확정**
- 일자: 2026-11-27 ([#117](https://github.com/Capstone-NOMOS/frontend/issues/117))

## 맥락

문서 탭(명세·API 계약·결정기록·인계 노트)은 목록을 한 번에 다 그렸고, 받은 편지함 알림은 30개씩 받았다.
대시보드 칸반은 칸마다 4장만 보이다가 "더 보기"를 누르면 모든 칸이 한꺼번에 펼쳐져 화면이 계속 길어졌다. 긴 제목은 카드 밖으로 넘쳤다.

## 결정

- **목록은 처음 10개, "더 보기"마다 20개.** 받은 편지함 알림(`limit` 10 → 20, `before` 커서)과 문서 4개 탭이 같은 간격이다.
  명세·계약은 서버가 전부 주고 노트는 최신 50개까지라 화면에서만 잘라 보인다. 결정기록은 서버 `limit`을 늘린다(상한 200).
- 명세 상단의 기능 키 칩은 아직 안 보이는 명세여도 먼저 펼친 뒤 앵커로 간다.
- **태스크 전용 페이지는 만들지 않는다.** 명세 §4 화면 목록에 없다(태스크 보드는 S-3 대시보드 안).
- **칸반은 칸마다 최대 26rem 안에서 따로 스크롤**하고 "더 보기/접기"를 없앤다. 칸 끝에 닿아도 페이지로 넘기지 않는다(`overscroll-contain`). 스크롤바는 숨기지 않는다.
- 카드 제목은 **2줄까지만** 보이고 `…`로 자른다(`line-clamp-2`). 전체 제목은 `title` 툴팁.

## 재검토 조건

- 태스크가 200개를 넘어 페이지를 나눠 받아야 하거나, 담당·기능별 필터·검색이 필요해지면 명세에 화면을 추가하고 태스크 페이지를 만든다.
- 노트가 50개를 넘어 예전 노트를 봐야 하면 BE에 이전 페이지 커서를 요청한다.
